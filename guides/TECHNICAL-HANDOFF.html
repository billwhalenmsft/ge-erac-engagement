For your Power Platform administrator

GE Verisk ERAC — Lite CRM · Technical Handoff Guide

Audience: the Power Platform administrator / IT team who will import, own, and operate the ERAC Lite CRM. Companion docs: BUSINESS-TRANSITION-GUIDE.md (why) and PARTNER-TAKEOVER.md (for an SI such as PwC).

1. What you're installing

A Dynamics 365 / Dataverse model-driven application — the "ERAC Lite CRM" — delivered as a genericized, self-contained Power Platform solution. It has no dependency on the Microsoft demo environment it was authored in, no premium connector requirements, and no Power Automate cloud flows (engagement AI, if used, is an optional Copilot/Azure Function sidebar — see §6).

Components created by the solution

Component Detail
Standard-table extensions Custom erac_* columns on account, contact, task, appointment (cedent flags, tier, partnership rating, function, Kanban stage, etc.)
5 custom tables erac_partnershiprating, erac_riskassessment, erac_treaty, erac_reserveadequacy, erac_dispute
Views (saved queries) Filtered views incl. "ERAC Cedents — Active" (erac_iscedent = true AND statecode = 0), ERAC Contacts, and per-table default views
Sitemap / app The ERAC Lite CRM model-driven app + erac_LiteCRM_SiteMap navigation
Web resources Dashboard / analytics HTML+JS resources (portfolio analytics, PRR dashboard)

The erac_ prefix is intentional and stays. It is solution-based (Enterprise Risk & Advisory Consulting), not a personal or environment identifier. Everything that did identify the source maker/environment (org host, environment GUID, solution GUID, author) has been genericized out of the package — that's what makes this installable in your tenant.

2. Prerequisites

  1. A Power Platform environment with Dataverse (a production or trial environment you control).
  2. System Administrator or System Customizer security role in that environment.
  3. The erac publisher prefix is created by the solution import (do not pre-create a conflicting one).
  4. Dynamics 365 / Power Apps licensing for the users who will access the app.
  5. (Optional, for the CLI path) Power Platform CLI (pac) authenticated to your environment.

No on-prem gateway, no premium connector, and no external service dependency are required for the core CRM.

3. Install — the fast path (Power Platform admin center)

  1. Go to make.powerapps.com → select your target environment.
  2. Solutions → Import solution → Browse → select the provided ERACLiteCRM_managed.zip.
  3. Accept the defaults (no connection references or environment variables need mapping for the core CRM). Click Import and wait for completion (~10–30 min depending on environment).
  4. Open the ERAC Lite CRM app from the app list. The navigation, views, and tables are present.

Load starter data (optional but recommended for a first look)

The package ships illustrative seed cedents/contacts so the app isn't empty. To load them into a fresh environment, use the provided provisioning script (data phase only):

cd customers/ge_erac/dataverse/scripts
.\Provision-EracDataverse.ps1 -OrgUrl "https://YOUR-ORG.crm.dynamics.com" -Phase Data

Before pilot go-live, replace seed data with your real cedent portfolio (§5).

4. Install — the scripted path (for repeatable / partner deployments)

If you prefer infrastructure-as-code over point-and-click, the same environment can be stood up from the imperative provisioning scripts (schema → data → UI), which are idempotent and safe to re-run:

cd customers/ge_erac/dataverse/scripts

# Full stand-up (schema + demo data)
.\Provision-EracDataverse.ps1 -OrgUrl "https://YOUR-ORG.crm.dynamics.com"

# Or phase-by-phase
.\Provision-EracDataverse.ps1 -OrgUrl "https://YOUR-ORG.crm.dynamics.com" -Phase Schema
.\Provision-EracDataverse.ps1 -OrgUrl "https://YOUR-ORG.crm.dynamics.com" -Phase Data

# Preview only (no writes)
.\Provision-EracDataverse.ps1 -OrgUrl "https://YOUR-ORG.crm.dynamics.com" -WhatIf

Which path to use? The managed solution ZIP is the turnkey, supported handoff — use it for the customer's own environment. The scripts are the build/repro harness and are how a partner reproduces or extends the environment. Both land the same result.

The model-driven app + sitemap are part of the exported solution — you do not need to hand-rebuild them. (They cannot be created via raw API, which is exactly why the package is delivered as an exported solution rather than pure scripts.)

5. Post-install configuration

  1. Assign security roles — grant your ERAC users access to the app and the erac_* tables via your standard Dataverse security roles.
  2. Set the default view — confirm "ERAC Cedents — Active" is the default on the Account table (it filters to erac_iscedent = true).
  3. Load real cedents — import your cedent portfolio (Excel/Dataverse import or the data script pointed at your source). Tag cedent accounts with erac_iscedent = true so they appear in the filtered views.
  4. Reporting — point Power BI at the Dataverse tables for portfolio reporting (the views are already shaped for this).

The cedent filter (important)

Every ERAC query is scoped by the cedent flag. When you build reports, flows, or integrations, filter on it:

$filter=erac_iscedent eq true and statecode eq 0

Example — all active cedents, richest columns:

GET /api/data/v9.2/accounts?$select=accountid,name,erac_partnershiptype,erac_tier,erac_overallrating&$filter=erac_iscedent eq true and statecode eq 0&$orderby=erac_overallrating desc

6. Optional — the Copilot / engagement-AI sidebar

The engagement log can be augmented with AI-generated summaries. This is delivered as an optional Azure Function + Copilot sidebar, not as a Power Automate flow, and is not required for the core CRM. If your team wants it:

  • Deploy the Azure Function (see the ERAC repo's function app) and set its Dataverse OData endpoint to your org host via environment variables — the package ships no hard-coded org host.
  • Or replace it with a Copilot Studio agent connected to Dataverse via the built-in connector (no custom API), surfaced in the app's Copilot pane.

Either way, this layer reads live Dataverse data and does not change the core schema.

7. What was genericized (so you can trust the install)

The package was run through an automated genericize → validate → leak-check → pack harness before release. It scrubs every source-environment identifier and fails the build if any survives:

  • Source org host (*.crm.dynamics.com) → your env via env-vars / relative paths
  • Source environment GUID, solution GUID → regenerated on import into your tenant
  • Author / maker identifiers → removed
  • Source repo references → removed

What is deliberately kept: the erac_ schema prefix, table/column/view/app names — because those describe the solution, not the author. This is the "solution-based naming, not personal naming" principle.

8. Verifying the install

  • [ ] Solution import completed with no errors.
  • [ ] ERAC Lite CRM app opens; sitemap shows Cedents & Contacts, Engagement, Risk & Partnership, Actuarial, Legal, Analytics.
  • [ ] Account table has the erac_* columns; "ERAC Cedents — Active" view returns rows.
  • [ ] The 5 custom tables (erac_partnershiprating, erac_riskassessment, erac_treaty, erac_reserveadequacy, erac_dispute) exist and open.
  • [ ] Dashboard/analytics web resources render.
  • [ ] No reference to a source org host or author anywhere in the app (search a web resource if in doubt).

If all boxes pass, the environment is a clean, owned install.

9. Support & extension

  • Extend it yourself — add columns/tables/views in your own solution layered on top; keep ERAC as the base.
  • Hand it to a partner — give them PARTNER-TAKEOVER.md; the scripted path (§4) is how they reproduce and extend the environment turnkey.
  • File map — see customers/ge_erac/dataverse/ (config/schema.json = full table/column/view/ sitemap definitions; scripts/ = provisioners; solution/ = the exported + genericized package and the genericize_and_build.py harness).
